## Preserve settled decisions

1. Preserve MWAN-340's translation model and MWAN-333's live-prefix behavior.
   Follow the plan's existing table ownership and reconciliation order.
2. Keep MWAN-507 additive. Use the planned typed protocol permissions and
   forwarding interfaces. Do not create another translation implementation,
   firewall authority, startup sequence, or independent health decision.
3. Keep provider names, prefixes, peer addresses, ASNs, and tunnel protocols
   configurable. Missing production values do not block implementation.
4. Preserve ordinary IPv4 independently of future IPv6 BGP. Sonic and Astound
   initially operate as ordinary MWAN providers. Etheric's native BGP,
   general tunnels, and BGP over tunnels remain later work under MWAN-507.
5. Leave WireGuard and the optional NDP plus NPT extension outside this epic.
   Do not make MWAN-341 closure depend on either. Keep new-circuit production
   exercises after October 2026.
6. Keep scope focused on the specified working behavior and observed defects.
   Add no speculative recovery framework or unrelated refactor.

## Enforce plain language

These requirements are mandatory for every agent working on this epic.
Apply them to chat, documents, code comments, commit messages, PRs, tickets,
the ledger, and handoffs. Do not relax them after context loss.

1. Ban "claudisms": metaphorical explanations, invented shorthand, abstract
   labels, performative narration, padded introductions, and vague reassurance.
   Rewrite each occurrence before publishing the text.
2. Use a concrete subject, a specific operation, and an explicit object.
   Explain network behavior before implementation details. Define unfamiliar
   provider terms on first use. Preserve exact technical identifiers.
3. Explain mechanisms in dependency order and events in chronological order.
   Answer status and decision questions directly before supporting evidence.
   Do not hide the conclusion at the end of an explanation.
4. Use literal verbs such as reads, writes, installs, validates, applies,
   rejects, permits, forwards, withdraws, and restores. Ban metaphors for
   data movement and vague substitutes for the actual operation.
5. Ban theatrical contrasts, rhetorical questions followed by answers,
   self-congratulation, apologies used as introductions, and summaries that
   merely repeat the preceding text. State the corrected fact directly.
6. Use complete, short sentences and familiar American English. Ban
   typographic dashes, sentence fragments, stacked abstractions, and bold
   fragments used as headings. Use lists only for steps or parallel facts.
7. State exactly what the evidence proves. Separate planned behavior from
   observed behavior. A build is not deployment proof, and a successful
   deployment is not downstream acceptance proof.
8. Report the result, relevant evidence, and remaining work. Omit personal
   activity logs and speculation from user-facing updates. Put operational
   details needed for resumption in the ledger.

7. Commit ledger updates with each logical change or a separate checkpoint.
   Preserve evidence needed by another machine outside temporary directories.
   The ledger is required even when the agent has its own memory system.
