# OpenTofu linting and retirement checks for `configsctl`

**Goal.** Give contributors one command to format OpenTofu code and one command to check it. Give reviewers a separate CI result that verifies when they can safely remove retirement code.

**Architecture.** `configsctl fmt` writes formatting fixes. `configsctl lint` checks source files and the repository’s guest configuration. A new `configsctl ci retirement --base <sha> --head <sha>` command compares two revisions and reads state only when the change removes a retirement instruction. The state check uses the backend and encryption settings from the trusted base revision.

**Execution.** Use `subagent-driven-development` and track the steps below.

**Enforcement.** Formatting, selected TFLint rules, proven loop simplifications, unresolved guest references, and unsafe retirement cleanup fail their respective checks. Repeated strings with uncertain meaning produce review findings. The implementation checklist below can serve as the work tracker.

## 1. Format and lint OpenTofu source

- [ ] **Add `configsctl fmt`.** Read `tofu.workspaces_dir` from the same settings as `configsctl lint` and run `tofu fmt -recursive` there. Dispatch formatting before vault access. Preserve the existing `tofu fmt -check -recursive` check and workspace metadata validation in `configsctl lint`. Preserve the existing meaning of `configsctl lint <paths>` for template callers. [Current native lint implementation](https://github.com/agoodkind/configsctl/blob/a050dc9d5c31bd5558d73dad210277ea0db6c08e/cmd/configsctl/nativeconfiguration.go#L44)
- [ ] **Add TFLint to the native lint command.** Enable `terraform_unused_declarations`, `terraform_typed_variables`, `terraform_naming_convention`, and `terraform_required_providers`. Pin the tested TFLint release in CI and document the same version for local use. Report a missing executable or a parser failure as a check failure. [TFLint rule catalog](https://github.com/terraform-linters/tflint-ruleset-terraform/blob/main/docs/rules/README.md)
- [ ] **Verify OpenTofu compatibility before requiring TFLint.** Run it against the actual module tree, including the workspace selector that uses a `const` variable and a computed module source. TFLint uses its own Terraform parser. If it cannot read valid project syntax, record the exact incompatibility and implement the affected checks against the active OpenTofu source before claiming coverage. [Workspace selector](../../../opentofu/modules/configuration/workspace/main.tf) · [TFLint compatibility](https://github.com/terraform-linters/tflint/blob/master/docs/user-guide/compatibility.md)
- [ ] **Test the public commands.** In a temporary checkout, verify that lint reports a misformatted file without editing it, `fmt` corrects it, and a second `fmt` makes no changes. Add one failing and one passing configuration for each enabled TFLint rule.

## 2. Report repeated values and enforce specific loop rules

- [ ] **Report repeated values by meaning and location.** Inspect host names, paths, URLs, and service identifiers in active module inputs and expressions. Group equal literals within one module and report the first and subsequent source locations. Exclude comments, declaration labels, and fields that require literal syntax. Report the field category and locations without printing potentially sensitive values. A repeated literal alone does not fail CI. An explicit contract, such as a guest reference that must resolve to a declaration, can fail CI under section 3.
- [ ] **Start with an HCL simplification that has a demonstrable replacement.** The overlay module iterates over `sort(keys(remote_file.files))`. OpenTofu already returns `keys()` in lexical order. Flag the redundant sort in this pattern and recommend `keys(remote_file.files)`. Use the HCL syntax tree to match expressions. Preserve loops that count duplicate paths or compare paths across workspaces, where simplifying the expression could change which conflicts the module detects. [Overlay configuration](../../../opentofu/modules/overlay/main.tf) · [OpenTofu `keys`](https://opentofu.org/docs/language/functions/keys/)
- [ ] **Check shell loops used for deployment.** Inspect provisioner commands and repository scripts they invoke. The first candidate is a loop that installs a declared collection of files individually when a `remote_file` resource with `for_each` can manage the same destinations, contents, and permissions. Report candidates for review. Promote a pattern to a blocking rule only after a real example and its native replacement demonstrate equivalent behavior. A retry loop waiting for Kafka health and a loop checking required input files are acceptance cases that must pass. [Native file deployment](../../../opentofu/vault/host/network.tf) · [Tack readiness checks](../../../opentofu/modules/tack/application/files/tack-compose-network.sh)
- [ ] **Test findings through `configsctl lint`.** Verify cross-file duplicates within one module, equal values in independent modules, and ordinary words in comments. Check that advisory findings leave the exit status successful, blocking findings return failure, and diagnostics identify the relevant file and line. Verify the HCL replacement with real OpenTofu inputs, including an empty collection.

## 3. Require guest references to resolve

- [ ] **Give each managed guest one declaration in its owning configuration.** Use its stable service identifier as the key and preserve its node, VMID, and hostname. Derive guest entries in service mappings and lock metadata from that declaration. Keep network definitions and host-level lock targets independently identifiable. The Tack QA configuration already distinguishes guests used by `module.base` from the larger set requiring locks, so `guest_keys` alone cannot serve as the complete inventory. [Tack QA configuration](../../../opentofu/modules/configuration/tack/qa/main.tf)
- [ ] **Check the producer and its consumers.** Extend the existing provider-free configuration evaluation to expose managed guest declarations and guest references. Check references across affected roots, including service mappings, module instance keys that identify guests, and guest locks identified by node and VMID. Fail lint on an unresolved identifier, conflicting declarations, or a guest lock that resolves to a different guest. Report the owning root and source location. A consumer copying stale metadata must not count as a declaration.
- [ ] **Use Sonic as the retirement regression.** Trace the fields MWAN reads from `isp_sonic_suburban`. Remove obsolete guest references. Where a consumer still needs network configuration, reference that network configuration directly. Test that deleting the guest declaration makes a surviving guest reference fail, while an independently declared `sonic_1` network still passes. [MWAN configuration](../../../opentofu/modules/suburban/mwan/configuration/main.tf)

## 4. Verify state before deleting retirement instructions

- [ ] **Detect what the PR removes.** Compare parsed `removed` targets in the base and head revisions. Handle a deleted block, a changed `from` address, and deletion of the whole root. Moving a block between files in the same module with the same address should pass without a state read. For a removed target in a shared module, identify every consuming root and its module address in the base revision.
- [ ] **Read every affected workspace through OpenTofu.** Resolve each backend from the base revision, including its named workspaces. For Sonic’s default workspace, the backend specifies Cloudflare R2 bucket `tofu-state` and key `suburban/simulators/sonic.tfstate`. Its configuration enforces AES-GCM encryption using `var.vault_tofu_state_passphrase`. The CI job needs read-only backend access and the decryption input. Reuse `configsctl`’s private state inspection code and keep state contents out of logs and artifacts. [Sonic backend](../../../opentofu/suburban/simulators/sonic/backend.tf) · [Encryption configuration](../../../opentofu/suburban/simulators/sonic/encryption.tf) · [Existing state reader](https://github.com/agoodkind/configsctl/blob/a050dc9d5c31bd5558d73dad210277ea0db6c08e/internal/statemigration/native.go)
- [ ] **Return a decision for the exact revision.** Block cleanup if any state contains the target or a descendant. Match address components and instance keys so `module.suburban_backup` does not count as a descendant of `module.suburban`. Also block cleanup if the job cannot enumerate workspaces, locate a required state, read it, or decrypt it. A successfully read state with zero matching instances passes. The check reports whether OpenTofu still tracks the address. The source checks cover remaining guest references.
- [ ] **Isolate the credentialed CI job.** Use the trusted workflow, verifier binary, and base backend configuration. Read proposed source as data. Do not execute the proposed revision with state credentials. Publish the result against the head SHA under review and require a new result when that SHA changes.
- [ ] **Test with real encrypted OpenTofu state.** Cover an empty state, a remaining indexed descendant, an unrelated module with a similar name, and two workspaces where only one completed removal. Exercise missing state, denied access, and an incorrect passphrase. Verify that the command leaves state unchanged and does not print a known sensitive test value. Verify R2 access independently before requiring the production check. The current Sonic object contents have not been verified.

## 5. Roll out in reviewable changes

- [ ] **Review the `configsctl` changes in three groups.** Group formatting and source lint together. Review guest validation with its configuration contract. Review the credentialed retirement verifier independently. Include CLI tests and usage documentation with each group. Run `make check` in `configsctl` before committing each change.
- [ ] **Adopt the reviewed tool in `configs`.** The current wrapper runs `configsctl@main`. Pin the known working revision before merging changes that introduce a required lint dependency. Advance to the tested revision together with CI tool installation and the corresponding configuration changes. [Current wrapper](../../../configsctl)
- [ ] **Require checks only after testing the real repository.** Run `./configsctl lint` across `configs`, review advisory findings, and correct blocking violations. Compare affected configuration outputs and planned resource actions before and after refactoring. Require the existing `configs lint` check and the separate retirement check after each demonstrates both a passing case and an intentional failure. Ordinary source lint must run without R2 credentials.
